# 0.1.3

Broader colour coverage, safer defaults, and protection for annotated highlights.

## Colour mapping

- Recognise the complete Highlightr / Highlightr Plus default palette, not just the six core colours. Pink, cyan/aqua, grey, and the higher-opacity ("floating") variants of each colour now map exactly instead of being guessed. Pink maps to red, cyan/aqua to blue, and grey to a plain (uncoloured) highlight, since Obsidian has no native grey.
- Class-based highlights are matched against the nine stock `hltr-<name>` classes, with grey mapping to a plain highlight.

## Custom colours are left for you to decide

- A colour that is not a recognised default no longer receives an automatic best-guess suggestion. Its row in the review table is left blank ("— choose —") so you consciously pick a colour or skip it. This removes the risk of a wrong auto-suggestion on an unusual shade.
- The conversion plan now reports an "undecided" count alongside convert and skip. Undecided rows are left untouched when you convert.

## Annotation safety

- Highlightr Plus can attach metadata to a highlight (`data-note`, `data-tags`, `data-name`, `data-type`). Converting such a highlight to native syntax would discard that metadata, because native highlights cannot carry it. These highlights are now detected and treated as unsafe: they are skipped and counted, never silently converted.

## Build and repository

- The project now builds with npm and commits a `package-lock.json`, so builds are reproducible from a clean checkout.
- Added a README and an MIT licence.
